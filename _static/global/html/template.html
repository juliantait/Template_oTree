Mode 3 — inner-card scroll

Opt a card into .inner-scroll and it goes back to the old model: the card stops at --inner-scroll-max and this middle region scrolls inside it while the header and footer stay pinned. The results page uses it so a long payout table scrolls inside the receipt rather than growing the window.

Scroll this region: the styled scrollbar, the soft edge shadow, the content fade and the wide low V cue below all appear only while there is more to read, and clear at the end.

Every page but the results page is Mode 1 whole-window scroll instead — the card grows and the page scrolls, so nothing a participant needs is ever hidden inside a box.

This filler exists only to make the region taller than the capped card, so the inner scroll is demonstrated rather than described. A real page's own content plays this role.

One more line of filler, so the region overflows at a comfortable desktop height and the affordances are unmistakably present for anyone flicking through the screenshots.

Design reference

Mode 2 — single-page fit

A short desktop page marked data-single-page is fitted into one viewport by global.js — font and spacing only, never transform or zoom (which would trap the tab-monitor overlay inside the card). The decision controls are never pinned; they stay after the reading, below.

If fitting would need a body font below the legibility floor, the page gives up and scrolls the whole window instead (Mode 1).
