{# THE EXPERIMENTER DASHBOARD AS AN ADMIN TAB (Julian, 2026-08-13). HOW THIS WORKS — a SUPPORTED oTree extension point, not an injection: at session creation oTree scans every app in the sequence for a template named /admin_report.html (otree/models/session.py, _set_admin_report_app_ names) and, if one exists, renders a "Report" tab in ITS OWN session tab bar (otree/templates/otree/Session.html) whose page includes this file (otree/views/admin.py, AdminReport). Nothing here templates over or patches oTree's pages, so an oTree upgrade that keeps the documented admin-report feature keeps this tab. A CONVENIENCE LAYER, DELIBERATELY THAT WAY ROUND: the dashboard's own URL (/experimenter_dashboard/) is the primary surface and must keep working unchanged with this file deleted, broken, or invisible. If the iframe below ever renders nothing, the link above it — and the URL typed by hand — still work; nothing about the dashboard lives here. dashboard_url comes from outro.vars_for_admin_report, which reads experimenter_dashboard.URL_BASE (one implementation of the path) and is internally defensive because oTree calls it UNGUARDED — a raise there would 500 this tab. NB the tab appears on sessions CREATED after this template shipped: oTree freezes the app-report scan into the session row at creation. Older sessions use the standalone URL, which is the primary surface anyway. #}

{# EXCEPTION (styling rule): inline size on the iframe — this renders inside oTree's OWN admin page, where the template's stylesheets are deliberately not loaded, so there is no shared component to compose. HEIGHT: 100dvh, not the old 78vh (Julian, 2026-08-23). oTree includes this file (see the header note) BELOW its own chrome — the navbar, the session tab bar and the app_name / round_number form row (AdminReport.html's `{ % formfield %}` table). At 78vh the whole Report page fit inside one viewport, so nothing scrolled: that chrome was stuck at the top and the dashboard could never own the screen, with a strip of empty page left below. A FULL viewport-height iframe makes the page taller than the window, so the operator can scroll the chrome out of the top and the dashboard fills the screen; the dashboard's own table then scrolls INSIDE the iframe as before. `dvh` (dynamic viewport height) is the unit base.css already uses, so it tracks whatever screen is viewing it rather than a stale fixed vh. display:block: an iframe is a REPLACED INLINE element by default, so it sits on the text baseline and leaves a few px of descender space beneath it — the thin "leftover row" under the embed. block removes it. box-sizing:border-box: so the 1px border is counted INSIDE the 100dvh rather than added to it — otherwise the iframe is viewport+2px tall and overshoots the screen it is meant to fill exactly. Verified at three viewport heights by scripts/tests/dashboard_embed_height_test.py. #}
