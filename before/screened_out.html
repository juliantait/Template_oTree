{{ block content }} {% include '_static/global/html/css_bundle.html' %} {# THE SCREEN-OUT PAGE. Served by before.welcome in place of consent for a participant whose device type is not in `allowed_devices` — see welcome.get_template_name and _apply_device_gate. It is the FIRST and ONLY screen such a participant ever sees, so it is a full narrative card like every other participant-facing page, not a bare error message. (Doc comments are ibis comments, { # … # } without the spaces. An HTML comment would not do: ibis parses { { } } inside one, and — measured on this very file — anything written with SPACED braces is not a comment at all and renders on the page for the participant to read.) IT OFFERS TWO PATHS AND THEY ARE NOT EQUAL. * SWITCH DEVICE — reversible, and the one we want taken. The wall is SOFT: reopening the study on an accepted device before consent CLEARS the screen-out and this page stops appearing, so "your place is still open" is literally true. It needs no control at all, which is the point — the participant simply leaves. * END THE STUDY — IRREVERSIBLE. Once they return the submission on Prolific they can never take part. So it is the SECONDARY action visually (.exit-button, a quiet outline; never a style= attribute), it sits below the switch-device panel, and its label says what it does. THE WAY OUT IS A REAL LINK, AND IT CARRIES NO COMPLETION CODE. * A REAL , not a scripted button. The implementation this was adapted from used onclick="completed()" with no href, so a participant whose JavaScript had not run had NO way off the page at all — a dead end on the one page whose entire job is to offer a way out. Pinned by tests/screenout_softwall_test.py (JS-free link) and render_check's screened_out_nojs scenario. * NOT .next-button: global.js's Enter handler clicks the first .next-button on the page, and an irreversible exit must never be one keystroke away by accident. * NO CODE: the destination is the platform's own site (`screenout_return_url`), so their submission stays OPEN and returning it stays THEIR decision. A completion code would close it the instant they clicked, contradicting the sentence above it. * ESCAPED: ibis does not auto-escape, so the URL goes through |escape even though it comes from config — the rule is about the attribute, not about the source of the value. SAY "PHONE", NEVER "MOBILE DEVICE": a study may accept tablets and reject phones, so "mobile device" would be untrue for the reader. Every sentence about what happened is chosen by `screenout_cause` (the DETECTED type) and every sentence about what to do names `allowed_devices_phrase` (what the study accepts), so the copy is accurate for any allow-list, not just "computers only". #}
